## 2024-03-20 - [Prisma Multiple Counts Optimization]
**Learning:** For Prisma database queries, executing multiple separate `count()` calls on the same table with different conditions causes unnecessary database roundtrips. Prisma's `groupBy` feature can calculate metrics for all statuses in a single query, significantly reducing latency and connection pool overhead.
**Action:** When a dashboard or aggregate view requires counts grouped by categorical fields (like `status`), always use a single `groupBy` combined with application-level reduction rather than issuing separate `count()` queries per status.
## 2024-05-24 - [Push filtering to database using Prisma native column comparison]
**Learning:** [When dealing with lists of entities in Prisma where application-side filtering exists (e.g., `attemptCount < maxAttempts`), you can significantly improve performance and avoid "N+1" overhead or pulling unnecessary data by pushing this logic to the database using Prisma 5.0+ native column comparison `this.prisma.model.fields.field`. However, unit tests using mock Prisma stores must explicitly implement `mockPrisma.model.fields` property handling for custom logic mock implementation to work correctly.]
**Action:** [Prefer `this.prisma.model.fields.field` for comparing two fields natively in queries instead of `.filter()` post-fetch. Always update `mockPrisma.ts` when introducing native column features into Prisma queries.]
