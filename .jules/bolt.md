## 2025-01-23 - Prisma Direct Column Comparisons and Mocking
**Learning:** Prisma's `.fields` property (e.g. `prisma.model.fields.fieldName`) allows direct native column comparisons pushing query filtering to the database level rather than application side (which avoids issues like fetching unnecessary rows into memory). However, when utilizing this feature, the mocked Prisma implementation for testing (like `mockPrisma.ts`) must be explicitly updated to handle Prisma `FieldRef` object comparisons (where the object contains a `name` property). If not handled in the mock, in-memory array filtering will fail silently or behave incorrectly.
**Action:** When implementing database level column comparisons with Prisma `.fields`, always make sure to mock the `FieldRef` behavior correctly in the mock database tests (`apps/api/test/mockPrisma.ts`) to maintain a green test suite. Ensure application-level `.filter` array loops are removed when the equivalent SQL is implemented.
